# 芯片替代料智能匹配工具

双击 `启动匹配工具.bat` 打开桌面 GUI。程序会自动读取 `products/MCC/clean` 中清理后的 MCC CSV，无需先运行 Notebook。

`clean` 中的文件采用 UTF-8 单表头标准 CSV：第一行是规范化字段名，第二行开始全部是数据，可以直接用于 Pandas、数据库导入或其他程序，不需要 `skiprows`。

使用方法：

`products/MCC/clean` 中的 CSV 是当前运行时的候选数据源。当前版本没有建立或读取 SQLite 等本地数据库。客户正在使用的型号无需存在于 MCC CSV 中；参数既可以手动输入，也可以按物料号自动填入。

1. 自动填参时无需预先选择物料类型；手动输入时仍可直接选择类型。
2. 在 GUI 中输入 DeepSeek API Key 和客户当前使用的型号，然后点击“识别类型并自动填参”。程序先让 DeepSeek 从现有类别中识别产品类型并自动切换；只有制造商和料号都与对应 CSV 明确一致时才采用 CSV 参数，否则继续调用 DeepSeek 填参。
3. 制造商菜单通常保持空白即可。只有 DeepSeek 提示同一料号可能对应多个制造商时，才选择正确制造商并重新查询；该选择会同时约束物料类型识别和参数提取。
4. `封装类型`为必填硬约束；配置、功能数、极性、沟道等分类参数填写后也作为硬约束。
5. 电气参数至少填写一项，空白参数不会参与匹配。
6. 点击“开始匹配”，程序只从相应的 MCC CSV 中推荐候选物料。
7. 结果先按关键参数状态（通过、待确认、不满足）分层，再按综合得分排列，可导出 CSV。
8. 勾选“精简显示”可只看评分、硬约束、关键参数和风险；勾选“只看车规级”可隐藏非车规候选，两个筛选可以同时使用。
9. 精简显示不删除导出字段；“只看车规级”开启时，导出的 CSV 也只包含车规级候选。

## DeepSeek 自动填参

API Key 可以直接填入 GUI 的密码框，不需要使用终端。输入内容默认隐藏，本程序只在当前运行期间保存在内存中，并通过 HTTPS 的 `Authorization` 请求头发送给已配置的 DeepSeek 接口；不会写入源码、CSV、配置文件或匹配结果。关闭程序后需要再次输入。请让每位客户使用自己的有效 Key，不要把公司共用 Key 写死在代码或随程序分发，否则他人可以从程序文件中提取并使用它。

如果电脑已经设置了 `DEEPSEEK_API_KEY` 环境变量，GUI 会用它预填密码框，原来的部署方式仍然兼容。环境变量不是必需项。

默认调用 `https://api.deepseek.com/chat/completions`，模型为 `deepseek-v4-flash`。如需切换，可设置 `DEEPSEEK_MODEL`；只有在使用可信的兼容代理时才应设置 `DEEPSEEK_BASE_URL`，因为代理会收到 API Key。代理地址必须使用 HTTPS，仅 `localhost`、`127.0.0.1` 或 `::1` 回环地址允许 HTTP，避免在网络中明文传输 API Key。

自动填参先要求 DeepSeek 从 GUI 实际支持的产品类别中选择一个类别；无法唯一识别或不属于支持范围时不会强行切换。同型号存在制造商歧义时，GUI 会要求从制造商菜单选择后重试，不会擅自采用某一公司的参数。参数阶段只接收识别后类别已有的字段，并锁定分类阶段确认的制造商。分类值必须能对应 GUI 的现有选项，数值也必须通过匹配模型的完整格式校验；未知字段、不确定字段和非法值会被跳过，不会直接进入匹配。DeepSeek 的回答不是原厂规格书或经过验证的元件数据库，自动填入后仍须核对制造商、封装、测试条件、Pinout 和原厂 datasheet，再点击“开始匹配”。

## 打包 Windows 试用程序

推荐使用 PyInstaller 的单目录模式。成品包含 Python 运行时、程序依赖和 18 个 clean CSV，客户无需安装 Python 或 Visual Studio Code。

首次打包时，在项目虚拟环境中安装构建依赖：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-build.txt
```

然后双击 `打包Windows程序.bat`，或运行：

```powershell
.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean chip_matching_gui.spec
```

输出目录为 `dist\芯片替代料匹配工具`。对外试用时应把这个文件夹整体压缩为 ZIP 再发送，不能只发送其中的 EXE。客户完整解压后，双击 `芯片替代料匹配工具.exe` 即可运行。

`build/` 和 `dist/` 都是可重新生成的打包产物，已由 `.gitignore` 排除。正式公开分发时还应考虑 Windows 代码签名、SmartScreen 提示和第三方依赖许可证。

## 更新和清理 MCC 产品表

将 MCC 原始导出表放入 `products/MCC/raw`，然后运行：

```powershell
python clean_catalogs.py
```

脚本会把清理后的 CSV 写入 `products/MCC/clean`，原始文件不会被修改。清理规则：

- 数据区整列为空时删除该列，因此 GUI 不再显示该参数。
- 没有字段名的列也会删除并记录，因为无法判断其参数含义。
- 原始产品类别行和单位行不写入 clean 文件；字段单位保留在字段名中。
- 字段名中的换行、不间断空格和连续空格会合并成普通空格。
- 数据单元格会移除首尾 Tab、NBSP、普通空格等 Unicode 空白，但保留内部字符，避免把 `2 4` 错改成 `24`；所有修正会写入清洗报告。
- 所有局部 NA 都保持未知，不再用近邻中位数填补。
- 如果物料的任意参数字段含逗号，删除整颗物料。
- 数值必须完整符合受支持格式；内部断裂、未知文字、比较符或多余斜杠不会再被静默截取。候选中的非法值按未知处理并提示风险，客户输入非法值时 GUI 会明确报错。
- 所有删列、删料、空白修正、无法安全解析的数值和保留空白数量都记录在 `products/MCC/cleaning_report.md`。

## 缺失感知匹配

- 只比较客户物料和候选物料双方都有值的参数，不会把 NA 替换成虚构值。
- `参数覆盖率`表示客户已填参数中有多少权重得到候选数据支持；覆盖率低于 50% 不推荐。
- Gower 相似度和参数覆盖率继续负责整体接近程度；方向规则是独立的产品配置层。
- 产品方向规则集中配置在 `matching_rules.py`，目前已启用 MOSFET、Switching Diode、SBD、FRED、Transistor、Zener、TVS 和 ESD。
- MOSFET：VDS、ID 要求替料不低于原料；RDS(on)、Qg、Trr、Qrr 要求替料不高于原料；VGS(th) Min/Max 要求相对偏差在 ±20% 内。
- 当前 MCC MOSFET 表没有 Qg、Trr、Qrr 字段；配置已准备好，今后 CSV 增加对应列后会自动生效。
- Power MOSFET 和 Small Signal MOSFET 的 `Channel=N+P` 参数按 `N值/P值` 解析；GUI 会自动切换为独立的 N沟道、P沟道输入框。
- N+P 关键方向规则逐侧检查，N、P 任一侧失败即标记“不满足”；关键字段缺少一侧时标记“待人工确认”。字段原始双值会完整保留在推荐结果和导出 CSV 中。
- N+P 的单值 VGS 视为两侧共享额定值；其他关键参数不会把单值自动复制到 N、P 两侧。
- Pre-biased Transistors 和 Small Signal Bipolar Transistors 在 `Polarity=NPN+PNP` 时按 `NPN值/PNP值` 解析；GUI 会切换为独立的 NPN、PNP 输入框。
- NPN+PNP 参数的两侧相似度取平均且整个字段仍只占一份权重；方向规则逐侧检查。候选只有一个值时不会擅自广播，关键字段标记“待人工确认”，其他字段降低覆盖率并提示风险。
- GUI 会自动识别以 `±数值` 为主、仅含少量明确 `+正值/-负值` 例外的字段并预填 `±`；裸 `±` 仅作为输入提示，不参与匹配计算。
- 单通道 MOSFET 的非对称 VGS（如 `+20/-16`）会分别比较正、负额定值，再取平均相似度。
- 标记为“关键”的规则会影响通过/待确认/不满足状态；“尽量较小/较大”等非关键规则作为方向偏好，不淘汰候选。
- 方向偏好占综合得分的 15%，Gower 接近度仍是主体。候选处于期望方向时方向得分为 100%，处于反方向时按相对偏差平滑扣分。
- Query 已填写但 Candidate 缺失关键参数时标记“待人工确认”；明确违反关键方向规则时标记“不满足”并降分。通过规则的候选始终优先显示。
- 结果同时显示综合得分、已知参数匹配度、覆盖率、可信度、缺失参数及风险提示。
- 相同封装名称不等于 Pinout 和尺寸已经验证，最终仍须核对原厂规格书。

若需要重新安装环境：

```powershell
python -m pip install -r requirements.txt
python app.py
```

匹配核心位于 `matching_model.py`，GUI 位于 `app.py`。后续可以在不改界面的情况下继续调整权重和约束逻辑。
